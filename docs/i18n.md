# Internationalization

The application and marketing site support `fr`, `en`, `it`, `nl`, `pt`, `de`,
`es`, `pl`, `zh`, `ja`, `ru`, `id`, `ko`. `zh` serves Simplified Chinese. The app
keeps French as its default; the marketing website keeps English.

## Ownership and adding a language

- `packages/types/src/locale.ts` owns `supportedLocales`, `SupportedLocale` and
  `isSupportedLocale`. Booking input validation and the email locale type reuse it.
- `apps/web/i18n/config.ts` owns autonyms, flags and representative regions.
- `apps/web/messages/<locale>.json` contains dashboard and storefront messages.
- The `emails`, `supplemental`, `landing-demos`, `inspections` and `invoices`
  message subdirectories keep server documents and small client previews separate
  from the full app catalog. Supplementary copy backs existing notification maps;
  new translated text should stay in these catalogs.
- `packages/email/src/messages` owns the new authentication email copy because
  shared packages cannot import app messages.
- `lib/i18n/format-locale.ts` resolves Intl and date-fns locales. Store timezone
  handling remains in `lib/utils/store-date.ts`.

The chosen `NEXT_LOCALE` cookie takes precedence for the interface and login
emails. Browsers may send regional tags such as `ja-JP` or `id-ID`. Booking
validation, stored reservation language and customer emails accept the same
13 language codes. Country-based email detection remains a fallback.

The five new catalogs were bootstrapped from English with automated Google
translation, followed by a review of common actions, navigation, rental terms,
Russian plural forms and critical Japanese authentication copy. A native-speaker
editorial review remains desirable. ICU arguments, tags and catalog keys are
validated against English. The extension adds no currencies or payment methods.

## Documents and existing boundaries

Contracts, inspection reports, invoices and their preview screens support the
five added languages. CJK PDFs use bundled Noto Sans CJK; Russian and other alphabetic PDFs use bundled
Inter. Font files and licenses are in `public/fonts/pdf`. Fonts are read locally,
traced into standalone deployments and never fetched from a font service during
PDF generation. Keep complete character coverage for customer and product names.

Inspection and invoice labels for the six older secondary languages still use
English, matching their previous availability. Merchant-authored product text,
legal terms and signed contract snapshots are not translated or rewritten.
The built-in legal templates retain their existing French/English availability.

The voice receptionist retains its separately validated eight-language list.
Adding a UI language does not declare support for a telephony provider's voices.

## Marketing demos and deployment order

Demo query parameters are validated against the registry and passed to the HTML
document and messages. The proxy rejects externally supplied internal language
headers. `scripts/landing-demo-posters.mjs` captures all 13 languages.

Deploy the app and its new `public/demo-posters/<scene>.<locale>.webp` assets before
the matching marketing-site release. The marketing site's `getDemoLocale` now
preserves all 13 languages, including for posters.

## Validation

From the repository root: `pnpm type-check`, `pnpm lint`, then a production build.
From `apps/web`, run the translation and related regression tests with a safe
local environment (no credentials or business database needed):

```sh
SKIP_ENV_VALIDATION=true NEXT_PUBLIC_APP_URL=http://localhost:3000 \
NEXT_PUBLIC_APP_DOMAIN=localhost:3000 pnpm exec tsx --test \
  lib/i18n/*.test.ts lib/landing-demos/*.test.ts lib/pdf/*.test.ts \
  lib/email/date-time.test.ts lib/utils/store-date.test.ts \
  components/storefront/account/reservation-outcome-messages.test.ts \
  components/storefront/account/reservation-detail-messages.test.ts
```

`catalogs.test.ts` checks key parity, ICU argument/tag preservation and actual
message formatting in all five languages. It also covers booking validation,
email locale selection, Russian plurals and poster registry parity. Font tests
check representative CJK and Cyrillic characters, including customer names.

For visual validation and poster generation after building:

```sh
pnpm --filter @louez/web demo:posters --start --browser /path/to/chromium
```

The capture server uses fictitious demo data without database credentials.

To refresh selected languages only, pass `--locales zh,ja,ru,id,ko` to
`demo:posters`. The generator retains the other scenes and languages in its manifest.
